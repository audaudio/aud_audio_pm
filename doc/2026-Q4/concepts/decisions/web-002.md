# web-002: The web control runtime

- Status: proposed
- Date: 2026-10-08
- Canonical source: topics/review-2026-10-08-engine-contracts.md
  (point 6); decisions/web-001.md
- Open work: measure the postMessage latency of the fallback path

## Decision

On the web the control thread of the native engine becomes a Wasm
Worker: when the page is cross-origin isolated the engine module runs
with shared memory, the AudioWorklet thread and a Wasm Worker share its
heap, and the worker compiles graphs, decodes and loads assets and
frees retired resources, publishing prepared plans and buffers through
the same atomic hand-over the native engine uses. The worklet only
executes. Without cross-origin isolation the worker prepares plans and
assets and transfers them to the worklet with `postMessage` (plan
structures by structured clone, buffers as transferables), and the
engine runs with explicitly reduced guarantees: events are scheduled at
least one block plus the message latency ahead, meters arrive at a
lower rate over messages, and assets are copied, not shared.

## Why

- Each AudioContext has one audio-processing thread and worklets cannot
  spawn general-purpose threads, so compiling and loading cannot happen
  there.
