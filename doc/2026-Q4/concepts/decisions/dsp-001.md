# dsp-001: DSP packages take code only with clear provenance

- Status: proposed
- Date: 2026-10-07
- Canonical source: topics/graph-engines-and-audiokit.md,
  topics/licenses-and-dsp-sources.md (R20 to R22)
- Open work: ask the AudioKit maintainers about the unattributed
  Devoloop helpers; list the re-implementations the first effects
  ticket needs

## Decision

`aud_dsp_effects` starts from the AudioKit family's own code — DunneAudioKit's
Chorus, Flanger, StereoDelay and TransientShaper as named nodes, its envelopes
and filters as building blocks —, Freeverb, Signalsmith DSP and chowdsp_wdf;
Soundpipe modules are taken only after a per-module provenance audit — modules
ported from Csound (LGPL) or generated from GPL or LGPL Faust code are never
copied; their algorithms are re-implemented from the published literature (the
Costello reverb from its description, the Moog ladder from Stilson and Smith
or Huovilainen) or replaced by permissive alternatives (Freeverb, Signalsmith,
chowdsp_wdf, Airwindows). `aud_dsp_stk` takes STK itself (MIT-style) with
STKAudioKit's wrappers as the model. `aud_dsp_guitar_amp` takes Rhino and
DynaRage once the unattributed helper files are clarified or replaced.
`aud_dsp_synth` ports DunneAudioKit's Synth as the first instrument node of
the family; its resonant low-pass filter, adapted from an Apple code sample,
is re-implemented unless that sample's license is confirmed permissive.
Faust-generated code is accepted only from functions declared STK-4.3 or MIT
(license-002). Every node documents its origin in the package's notices file.

## Why

- R26 and R27; MIT labels on ported LGPL code do not make it MIT.
- The legally clean pool is large enough for the first releases.
