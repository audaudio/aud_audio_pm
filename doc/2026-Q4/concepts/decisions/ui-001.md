# ui-001: UI packages are Flutter widgets over the Dart models

- Status: proposed
- Date: 2026-10-07
- Canonical source: topics/graph-engines-and-audiokit.md (R17, R18)
- Open work: pick the canvas approach (CustomPainter plus
  InteractiveViewer, or a widget per node) in the first UI ticket

## Decision

`aud_audio_ui_graph_edit` and `aud_audio_ui_piano_roll` are pure Flutter
packages that render and edit Dart data models — a patch model ported from
AudioKit Flow (patch, nodes with positions, typed ports, wires) and a note
model ported from AudioKit PianoRoll (notes with start, length, pitch) — and
emit edits as callbacks. Binding those models to the engine's graph and to the
sequencer happens in thin adapter layers in the same packages, so the widgets
test headless and work with any engine state. The keyboard and controls
packages (ui-002) follow the same rule, as would a waveform widget.

## Why

- Flow's and PianoRoll's models are small, MIT and proven.
- Headless models keep UI tests fast and let the editors drive remote
  engines through OSC later.
