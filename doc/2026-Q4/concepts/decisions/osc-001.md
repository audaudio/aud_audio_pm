# osc-001: Every node has an OSC address

- Status: proposed
- Date: 2026-10-07
- Canonical source: topics/osc-addressing.md (R10)
- Open work: the network server (S7). The address grammar, the reply
  vocabulary and the timetag rules are fixed in ticket 18
  (`AudOscAddress`, `AudOscVocabulary`, `AudOscAdapter`)

## Decision

Graphs, nodes, inlets, outlets and parameters carry OSC 1.1 addresses
(`/graph/<id>/node/<id>/param/<name>` and the like, with `*`, `?`, `[]`, `{}`
and `//` patterns). OSC is the model of the Dart API and the wire format of
the network server in `aud_audio_osc`; it is an adapter, not the engine's
internal command model. Inside the engine commands are typed and numeric: node
handles, parameter indices, event structs and timestamps tagged with their
domain. The Dart-side router resolves addresses to handles before a command
enters a realtime queue, and the adapter converts OSC timetags (NTP absolute
time) into the engine's domains — immediately, host time, or beat time through
the transport — with explicit conversion rules. The engine replies and
notifies in the SuperCollider manner (`/done`, `/fail`, node lifecycle,
meters).

## Why

- OSC is the brief's model; sfizz already speaks it; SuperCollider shows
  it scales to a whole synthesis server.
- One addressing scheme lets the graph editor, the sequencer, remote
  controllers and tests speak the same language.
