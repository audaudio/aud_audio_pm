## Decision

Two more UI packages join the family, both pure Flutter and engine-free
in their widgets as ui-001 demands, with thin adapters to `aud_audio`.

`aud_audio_ui_controls` ports AudioKit Controls (MIT, 1.1.4): one
generic `Control` widget for a single bound value with a range, an
`onStarted` and `onEnded` callback and a `ControlGeometry` — horizontal
or vertical point, horizontal, vertical or two-dimensional relative
drag with sensitivities, absolute angle within an angular range, and
angular drag — and one `TwoParameterControl` for two values with a
`PlanarGeometry` — rectilinear, relative rectilinear, polar and relative
polar. A gesture layer averages all active pointers into one point
(touch and mouse). On these two primitives the package ships the same
implementations as the template: `ArcKnob` (arc from 45° to 315°, an
origin for bipolar values such as pan, the value shown while dragging),
`IndexedSlider` (integer steps, snapping), `PitchWheel` (springs back)
and `ModWheel`, `Ribbon`, `SmallKnob` (tap, then drag on either axis),
`Joystick` (polar) and `XYPad` (rectilinear with indicator padding).
Theming goes through an inherited `ControlsTheme` instead of the
template's copy-on-write color modifiers. A `ParamBinding` adapter
connects a control to a graph parameter by its OSC address, maps
`onStarted` and `onEnded` to parameter gestures (automation begin and
end, as VST3 and CLAP know them) and ramps the value.

`aud_audio_ui_keyboard` ports AudioKit Keyboard (MIT, 1.4.1): a
`Keyboard` widget with a `KeyboardLayout` — piano with configurable
spacer ratios and black-key proportions, isomorphic filtered by root
and scale, guitar with open pitches and fret count, vertical isomorphic
and vertical piano —, `latching`, `noteOn(pitch, normalizedPoint)` and
`noteOff(pitch)` callbacks and a key builder. A `KeyboardModel` collects
the key rectangles of the layout, turns all active pointers into the set
of touched pitches (highest key on top wins) and diffs that set into
note-on and note-off events, keeping the normalized touch point inside
the key for velocity and expression; `externallyActivatedPitches` shows
incoming MIDI or latched keys. The default `KeyboardKey` draws white and
black keys with colors, labels (the note name on every C by default)
and a flat-top option; a `MidiMonitorKeyboard` paints active pitches
read-only. A `NoteBinding` adapter sends the notes as MIDI events into a
graph event inlet or into the sequencer, with per-note expression from
the normalized point as an option.

Both packages carry Flutter golden tests and a page in the cookbook app;
their models are headless-testable like those of ui-001.

## Why

- The owner's request; both templates are MIT, small and proven, and
  their models translate one to one into Dart.
- Controls' two generic primitives make every further control cheap;
  Keyboard's model separates touch handling from layout, which Flutter
  needs as much as SwiftUI does.
