# abi-001: The C ABI contract between engine and DSP packages

- Status: proposed
- Date: 2026-10-08
- Canonical source: topics/review-2026-10-08-engine-contracts.md
  (point 9); decisions/interop-001.md
- Open work: decide between a shared engine library and a static engine
  in the umbrella on each platform. The header is written: ABI 0.2 in
  `aud_audio_core/src/aud_abi.h` (ticket 18); in major 0 the minors must
  match exactly, the promise of this decision starts with 1.0

## Decision

The C ABI of `aud_audio_core` is a versioned plugin contract, not a bare
vtable. Every struct starts with its size and the ABI carries a major and
minor version; a package registers its node types with the ABI version it was
built against, and the engine refuses incompatible majors and negotiates
capabilities for minors. Functions are tagged with their thread affinity
(realtime, control, off-line, as sfizz tags them). Memory crossing the ABI is
owned by the engine: nodes receive allocator callbacks for non-realtime work
and never allocate in the process call. No C++ exception crosses the boundary;
errors are codes with a message callback. Each node type declares
capabilities: in-place processing, variable block support, channel limits,
latency and tail reporting, state serialization (versioned blobs for save and
load), reset semantics on transport stop and seek. A DSP package exports one
registration symbol and keeps every other symbol namespaced; packages do not
link the engine — they receive host callbacks through the ABI, so no core
state is duplicated across libraries. Compatibility policy: a package built
against ABI major N runs on every engine of major N whose minor is at least
the package's; the engine reports the oldest package minor it still accepts,
and older packages keep running until the next major. For the web build every
package adds a contribution manifest — sources, dependencies, registration
symbol, compiler flags, pinned Emscripten version — that `aud_audio_web`
consumes (web-001). Pub versions do not replace this: caret ranges allow later
minors, so the ABI version check at registration is the real compatibility
gate, and the umbrella pins exact versions of the family.

## Why

- Independently compiled packages meeting in one process need exactly
  these rules; every plugin standard (VST3, CLAP, LV2) has them.
- A versioning error in the first plan: `^1.2.3` permits every minor
  below 2.0.0, so coordinated releases alone cannot guarantee binary
  compatibility.
