# osc-002: Nodes take messages and answer through the engine

- Status: accepted
- Date: 2026-10-11
- Canonical source: tickets/2026-10-11-25-build-the-sfz-sampler-on-sfizz-for-ios-and-android.md
  (question 4)
- Open work: the network server (S7) forwards the routes; replies of

## Decision

A node with `AUD_NODE_CAP_MESSAGES` takes OSC messages below its route
`/graph/<g>/node/<n>/msg/`. The graph copies a message into a slot of its
own and delivers it to the node as an `AUD_EVENT_MESSAGE` event - queued,
scheduled, ordered and budgeted like every event; the node answers through
`AudHostApi.emit_message` on the audio thread; the graph copies the answer
into a reply ring, and the control thread takes it with the notifications.
In Dart, `AudGraph.sendMessage` sends and `AudGraph.messages` delivers the
answers. A message holds at most 1000 bytes of path and arguments. A node
that would allocate while it handles a message refuses it and reports
`AUD_ERROR_UNSUPPORTED`: the sampler refuses string and blob arguments,
which sfizz copies or parses, and its fork drops the messages that would
grow its regions on the audio thread.

## Why

- Most of sfizz's message API are queries; a transport without answers
  would keep little of it.
- On the event path messages stay sample-accurate and ordered with notes
  and parameters, without a second queue into the audio thread.
